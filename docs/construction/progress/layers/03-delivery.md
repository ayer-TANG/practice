## 职责

- `renderMarkdown(tasks) => string` —— **纯函数**，字符串进、字符串出
- 复制到剪贴板
- 下载 `.md` 文件

> **分工的落点**：`renderMarkdown` 在本层（可被 `node --test` 提取测试）；
> **复制与下载在 UI 层**——它们要碰 `navigator.clipboard` / `Blob` / `URL`，
> 只能人工验证。本层存在的意义就是把"生成什么"和"怎么送出去"分开。

## 硬约束

1. **`renderMarkdown` 必须是纯函数**，只有"复制/下载"这两个动作触碰浏览器 API
2. **不得被领域层依赖**
3. 不得修改 `Task`
4. 不得引入第三方 markdown 库——手写模板字符串即可
5. **本层不得出现 `clipboard` / `Blob` / `createObjectURL`**——那三个属于 UI 层。
   测试里有静态检查锁死这一条

### 关键实现决策

**分组只有两个，来源与 `fuzzy` 是行内标记。**
产品需求写明"唯一的分组规则：有截止时间 / 未识别到时间，二分"。
给 `source: 'manual'` 单开一个 `##` 分组会直接违反它。测试里有断言锁死这一点：
输出的 `##` 标题数量与内容必须与二分结构一致。

**Markdown 行内元字符要转义。**
任务文本是用户粘贴的聊天记录。一条含 `[` 的任务在未转义时会把后续内容全变成
链接文本——破坏可读性，而"可读"是本阶段的验收标准。
转义集合：`\` `` ` `` `*` `_` `[` `]`。
`#`、`-`、`+` 只在**行首**才有块级语义，而任务文本永远跟在 `- [ ] ` 之后，
不在行首，所以不转义（保持原文可读）。
`|` 不转义——输出里没有表格，管道符没有语义。

**换行压成空格。**
换行会把一个列表项截成两行，第二行不再是列表项。
当前数据流下不该出现（领域层按行切分、手动补漏是单行 `input`），
但防御成本只有一次 `replace`，不值得留这个口子。

**`renderMarkdown` 不排序。**
排序是 `sorter` 的职责。本层若自作主张排序，会掩盖上游的 bug。
测试里有一条断言专门锁死"组内保持入参顺序"。

**`fmtDeadline` 在 UI 层与本层各有一份。**
这是**有意的重复**，不是疏漏。两处展示需求可能分化（界面要短、Markdown 要完整），
共用会让两层耦合在一个最容易变的细节上。各 5 行，不值得抽。代码里有注释说明。

**空列表返回一句说明，不返回空串。** 复制出一片空白比复制出一句"没有任务"更让人困惑。

## 风险

| 风险 | 说明 |
|---|---|
| **`file://` 下剪贴板可用性未实测** | 三级链路（`clipboard API` → `execCommand` → 手动提示）都写了，但**哪一级会在真实浏览器里生效，不知道**。若前两级双双失效，用户会看到"请手动选中"——功能可用但体验降级。**这是本阶段最大的未闭合项** |
| **下载未实测** | `createObjectURL` 在 `file://` 下通常可用，但未验证。文件名含中文，个别浏览器/系统可能有编码问题 |
| **转义只覆盖行内元字符** | 行首敏感的 `#`、`-`、`>` 没转义。当前输出形态下任务文本永远不在行首，所以安全；但若将来改输出格式（比如去掉 `- [ ] ` 前缀），这个前提就失效了。测试里有断言锁定当前前提 |
| **`fmtDeadline` 两处重复** | 有意为之，但确实是两处需要同步的地方 |
| `execCommand` 已废弃 | 它是第二级回退。浏览器最终会移除它——但在那之前，它是 `file://` 下唯一的备选。移除时需重新评估 |
