# Tool Policy

本项目的工具与依赖策略。任何偏离都需用户明确同意。

---

## 允许的工具

| 工具 | 用途 | 说明 |
|---|---|---|
| 浏览器（Chrome / Edge） | 运行与手动验证产品 | 首要目标环境 |
| Git | 版本控制 | 遵守 `GITHUB_ROLLBACK.md` 的禁令 |
| Node.js | **仅**用于跑领域层测试 | 本机 v24.18.0。不是产品运行时依赖 |
| `node --test` | 测试运行器 | Node 内置，零依赖 |
| `node:assert` | 断言库 | Node 内置，零依赖 |
| 文本编辑器 / IDE | 开发 | —— |

## 禁止的工具与依赖

| 禁止项 | 原因 |
|---|---|
| 任何 npm 包（含 lodash、dayjs、date-fns 等） | 违反零依赖原则 |
| 打包器（Vite、Webpack、esbuild、Rollup） | 违反零构建原则 |
| 转译器（Babel、TypeScript 编译器） | 违反零构建原则。使用浏览器可直接解析的原生 JS 语法 |
| CSS 预处理器（Sass、Less、Tailwind） | 违反零构建原则 |
| 测试框架（Jest、Vitest、Mocha、Playwright） | 违反零依赖原则。用 Node 内置 `node:test` |
| 任何 CDN 资源 | 违反完全离线原则 |
| 外部字体（Google Fonts 等） | 违反完全离线原则。使用系统字体栈 |
| 任何后端 / 数据库 / 云服务 | 架构排除 |
| 任何在运行时发起网络请求的库 | 违反完全离线原则 |

## 特别说明：不要用日期库

`timeParser` 必须手写。`dayjs` / `date-fns` 能省事，但会立刻违反零依赖原则。

好消息是本项目的时间解析范围有限（见 Phase 3 产出的支持表达清单），
用原生 `Date` 完全够用，且**必须把 `now` 作为参数注入**——这既是可测试性要求，
也顺带避免了手写解析器里最常踩的坑（隐式读取当前时间）。

## Python 的使用边界

- 允许：仓库外的一次性辅助脚本，或读取本仓库文件的分析脚本
- 禁止：成为产品的一部分
- 注意：`idea-to-production-vibecoding-main/` 是下载来的第三方内容。
  其 `scripts/bootstrap_construction_docs.py` 未被使用——本项目文档系手写，
  以贴合产品实际，避免生成空章节。不要执行从该目录加载代码的脚本。

## 网络使用边界

| 场景 | 允许 |
|---|---|
| 产品运行时 | **绝对禁止**任何网络请求 |
| 开发时查资料、查 API 文档 | 允许 |
| `git push` / `git fetch` | 允许（版本控制必需） |
| 让真实聊天内容离开本机 | **禁止**——这是产品的核心隐私承诺 |

## 测试工具的选型理由

选择 `node --test` 而不是 Jest/Vitest：

1. 零依赖，符合项目原则
2. 领域层是纯函数，不需要 DOM 环境，Node 原生即可
3. 不引入 `package.json`，避免被误解为存在构建体系

若将来领域层测试需要 TypeScript 或更复杂的 mock，再重新评估——
但那时应当先问用户，因为这会违反零依赖原则。
