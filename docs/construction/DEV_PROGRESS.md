### 本轮目标

### 计划中的设计取舍（写代码前先定，避免边写边改）

| 取舍 | 决定 | 理由 |
|---|---|---|
| 行拆分口径 | 按 `/r?\n/` 拆行，一行 = 一条消息 | 粘贴的纯文本以换行分隔；无换行则无法可靠切分 |
| 反向词匹配范围 | **整行**匹配，不是子串 | 「收到，明天发你」含「收到」但是任务。子串匹配会把它误杀 |
| `text` 与 `raw` 的区别 | `text` = 去首尾空白的行；`raw` = 原始行。rule 任务二者仅差空白 | 二者为 UI 的两个用途（任务描述 / 核对原文）；本阶段不剥离发言人前缀 |
| 发言人前缀剥离 | **本轮不做** | 粘贴格式随客户端而异，无真实数据（A-001）时凭空猜格式属于「凭感觉写规则」。记入 Phase 8 校准项 |
| `id` 生成 | 确定性：`'r' + 行号` | 领域层须纯净可测，不能用 `Math.random()` |
| 领域层新增导出 | `isTaskLine`、`taskExtractor`、`sorter`、`makeTask`、`parse` | `makeTask` 让 UI 不必手搓 `Task` 形状（Phase 6 手动补漏要用） |

### 计划中的设计取舍（写代码前先定）

- **不回卷 ⇒ 值可能落在过去**。`sorter` 是升序，因此已过期的任务会**排在最前**。
  这与修复前（排到最后、显示 2027 年）相反——**正是想要的效果**：
  逾期项显眼，静默跳到明年才是灾难。

## Phase 8 / 禁用态可见性修复轮结果（2026-10-09）

### 根因：不是「太淡」，是「不存在」

原先 `button:disabled { opacity: .45 }`。在**白卡片**上，这个透明度的效果是：

```
opacity 0.45  ×  background rgb(255,255,255)  →  底就是卡片本身
opacity 0.45  ×  border #e2e5ea               →  轮廓消失
```

**按钮的轮廓彻底没有了。** 用户说「不显示」，字面上是准确的。

> 这条值得单独记：**用 `opacity` 表达禁用态，前提是元素本身有对比度余量。**
> 浅色卡片上的浅色按钮没有这个余量——压到 .45 就直接归零。
> 深色底或高对比度的元素上，同样的写法**不会**出问题，
> 所以这个坑只在特定配色下才显形，靠肉眼审代码看不出来。

### 怎么查出来的：换证据，不再猜

前半程一直在改代码、跑探针，全绿——因为探针**没有 CSS**，它根本测不到这一层。
转折点是发现本机装了 Edge，可以无头跑：

| 手段 | 得到什么 |
|---|---|
| `--dump-dom` | 按钮**在** DOM 里，JS 也执行了（`title` 已被写成说明文案） |
| `--screenshot` | 按钮**肉眼几乎看不见** |
| 注入 `getComputedStyle` | `opacity: 0.45` / `background: rgb(255,255,255)` —— 定量确认 |

**前两个手段只是「像」，第三个才是证据。** 截图能看出「好像很淡」，
但分不清「淡」和「没渲染」；只有量出来的数值能定案。

### 改了什么

1. **禁用态改为显式配色**（不再用整块透明度）：

   | 状态 | `color` | `background` | `cursor` / `pointer-events` |
   |---|---|---|---|
   | 可用 | `rgb(27,29,33)` | `rgb(255,255,255)` | `pointer` / `auto` |
   | 禁用 | `rgb(107,114,128)` | `rgb(241,243,246)` | `default` / `none` |

   文字与底色两个维度都拉开。`pointer-events: none` 保留——
   不关的话 `:hover` 仍匹配 disabled 元素，划过会变色，看着像可点。

2. **`input` 事件兜底**：`onPaste()` 除让 `input` 结账外，另排
   `setTimeout(..., 0)`，等默认粘贴动作写完 `value` 后若 `pendingPaste`
   仍是自己就结账。**理由是失败形态排序**——
   「按钮永远不亮」比「删错了」更糟：用户会以为功能根本不存在。

### 计划的偏离

**多做了两件计划外的事，都是「顺手把真问题修掉」而非扩范围：**

1. 加了 `setTimeout` 兜底（原计划只改 CSS）。理由：用户报的是「不显示」，
   而这个词同时覆盖两种失败——「看不见」和「从没亮过」。两个都堵上才算修完。
2. **把「本机无法启动浏览器」这句话改正了。** 这句在 14 处文档里写着，
   **是错的**（无头 Edge 一直可用，只是没被发现）。留着它的代价是真实的：
   它让几轮工作停在桩测试上，包括这一轮的前半程。
   改法见「文档漂移」一节。

### 关键数字

| 项 | 值 |
|---|---|
| `node --test` | **417 passed / 0 failed**（未受影响） |
| 一次性 DOM 探针 | **35 passed / 0 failed**（原 10 组 28 项 → 12 组 35 项） |
| 无头 Edge | 改了 3 次取证命令，最终确认禁用态可见且与可用态可区分 |

### 探针自己出过一次错（如实记）

首轮跑出 **33 passed / 1 failed**。失败项是「兜底不会重复记账」的
「按钮回到禁用」，症状（点一次没删净、提示「还剩 1 段」）**看起来完全像产品缺陷**。

查下发现是**探针的脏状态**：记账列表在 UI 闭包里，DOM 桩拿不到；
第 8/9/10 组各粘贴过一次且没清空，记录累积着带进了第 12 组。
加 `resetPasteState()` 复位后 35/0。

> **教训一**：探针失败时，先问「是不是我的桩脏了」，再问「是不是代码错了」。
> 这两者的症状可以完全一样。
> **教训二**：这个探针的日志是**最后一次性打印**的，中途 `console.log`
> 会出现在输出顶端。我按 `tail` 找自己的调试输出，白找了好几轮。
> 定位它的正确做法是 `grep DEBUG`，不是 `tail`。
